# План переработки скина питомца и UI игрового экрана

Документ описывает, какие ресурсы, анимации и спрайты нужны для создания нового скина питомца и обновления UI игрового экрана. Содержит краткий глоссарий для тех, кто не знаком с терминологией.

---

## Глоссарий (кратко)

| Термин | Значение |
|--------|----------|
| **Спрайт** | Один статичный кадр изображения (картинка персонажа в определённой позе). |
| **Кадр (frame)** | То же, что спрайт — один «снимок» в последовательности. |
| **Анимация** | Последовательность кадров, которые сменяют друг друга во времени (как мультик). |
| **Скин** | Набор всех спрайтов одного питомца (idle, attack, dead и т.д.). |
| **Overlay** | Слой поверх основного изображения (например, эффект голода поверх питомца). |
| **RGB565** | Формат цвета: 16 бит на пиксель (5 красный, 6 зелёный, 5 синий). Используется в проекте. |
| **PROGMEM** | Хранение данных во flash-памяти микроконтроллера, а не в RAM. |
| **Прозрачность** | Цвет `0xFFFF` (белый) считается прозрачным при отрисовке спрайта. |

## 2. Ресурсы для нового скина питомца

### 2.1 Обязательные спрайты (минимум для работы)

Для **каждого** нового скина (Dragon, Robot и т.д.) нужны:

| Набор | Кол-во кадров | Размер (нативное) | Формат | Описание |
|-------|---------------|-------------------|--------|----------|
| **Idle** | 4 | 176×169 px | RGB565, PROGMEM | Цикл «ожидание» — питомец стоит/дышит/моргает. |
| **Egg idle** | 4 | 176×169 px | RGB565 | Яйцо с характером скина (покачивание). |
| **Egg hatch** | 5 | 176×169 px | RGB565 | Вылупление: яйцо → трещина → появление. |
| **Attack** | 3 | 176×169 px | RGB565 | Охота: замах → удар → возврат. |
| **Dead** | 3 | 176×169 px | RGB565 | Смерть: падение/затухание. |

**Итого минимум:** 19 спрайтов × (176×169×2 байт) ≈ **1.1 МБ** на скин (в PROGMEM или PSRAM при загрузке с SD).

### 2.2 Расширенные спрайты (по стадиям)

Если хотим различать питомца по стадиям (BABY, TEEN, ADULT, ELDER):

| Стадия | Idle | Attack | Dead | Примечание |
|--------|------|--------|------|------------|
| BABY | 4 | 3 | 3 | Маленький, «детский» вариант |
| TEEN | 4 | 3 | 3 | Средний размер |
| ADULT | 4 | 3 | 3 | Полноразмерный |
| ELDER | 4 | 3 | 3 | Старец (седой, медленный) |

**Итого расширенный скин:** до 4×10 + 4 + 5 = **49 спрайтов** (≈1.2 МБ). Яйцо и hatch обычно общие.

### 2.3 Технические требования к спрайтам

- **Формат:** RGB565 (16-bit), без альфа-канала.
- **Прозрачность:** Пиксели цвета `0xFFFF` (белый) не рисуются — «дырки» в спрайте.
- **Ориентация:** Центр персонажа примерно в центре кадра (для ровного позиционирования).
- **Конвертация:** Исходник (PNG, PSD) → массив C `const uint16_t name[] PROGMEM = { ... }`. Инструменты: ImageMagick, GIMP, онлайн-конвертеры для Arduino, или скрипт на Python.

## 6. Инструменты и конвертация

### Создание спрайтов

1. **Рисование:** Aseprite, Piskel, GIMP, Photoshop, Krita.
2. **Экспорт:** PNG с прозрачностью. Цвет прозрачности при конвертации → `0xFFFF`.
3. **Конвертация в C-массив:**
   - [image2cpp](https://javl.github.io/image2cpp/) — веб, выбирать RGB565, Arduino.
   - ImageMagick: `convert input.png -depth 16 rgb:- | xxd` + скрипт.
   - Python + PIL/Pillow: чтение PNG, вывод RGB565, запись в .h.

### AI-инструменты (для не-художников)

**Для TamaFi:** основной стек — **Perchance** (egg, hunger, референс) + **AutoSprite** (idle, attack, dead из 1 референса). Порядок: см. «Порядок использования инструментов» ниже.

### Порядок использования инструментов (пошагово)

```
Шаг 1  →  Perchance
          Промпт: "pixel art cute pet creature, tamagotchi style, front view, 176x176"
          (176×176 или 192×192 — ближе к целевому 176×169, меньше потерь при масштабировании; 128×128 — маловато)
          Результат: JPEG (Perchance часто даёт только JPEG)
          → В Piskel/GIMP: открыть JPEG → заменить белый фон на прозрачность → экспорт PNG
          ↓
Шаг 2  →  Piskel или GIMP
          JPEG → PNG с прозрачностью (Color to Alpha / Select by color → Delete). Обрезать до 128×128 или 256×256, если AutoSprite требует конкретный размер.
          ↓
Шаг 3  →  AutoSprite
          Загрузить референс → Idle → экспорт → Attack → экспорт → Dead → экспорт
          (3 экспорта/день: можно за 1 день или растянуть на 3)
          Альтернатива: Ludo.ai — текст → спрайт → анимация (idle, attack, dead) за 30 кредитов
          ↓
Шаг 4  →  Perchance
          Egg idle: 4 кадра ("pixel art egg, slight tilt left/right, 176x176")
          Egg hatch: 5 кадров ("pixel art egg cracking, frame 1/2/3/4/5, 176x176")
          Hunger: 4 кадра ("pixel art hunger effect, stars, 176x176")
          ↓
Шаг 5  →  Piskel
          Масштабировать все кадры до 176×169, выровнять, экспорт PNG
          ↓
Шаг 6  →  image2cpp
          PNG → RGB565 → C-массив PROGMEM
          ↓
Шаг 7  →  SkinName.h + ui.cpp
          Добавить массивы, зарегистрировать скин
```

**Кратко:** Perchance (референс) → AutoSprite (idle, attack, dead) → Perchance (egg, hunger) → Piskel (масштаб) → image2cpp (конвертация).

**Альтернатива (если есть бюджет):** PixelLab paid — текст → полный набор анимаций (idle, attack, dead) одним запросом, canvas до 180×180.

## 7. Оценка памяти (ESP32-S3)

- **Flash:** Спрайты в PROGMEM. Один скин ~500 КБ. Несколько скинов — учитывать лимит прошивки.
- **RAM:** Буферы `petBuffer` (115×110×2) и `effectBuffer` (100×95×2) — общие для всех скинов.
- **PSRAM:** 8 МБ — хватает для canvas 368×368 (~265 КБ) и кэша скина (~1.1 МБ при загрузке с SD).
- **Рекомендация:** Подключать скины по одному на этапе разработки; при сборке можно исключать неиспользуемые через `#if PET_SKIN_GOLEM` и т.п.

## 8. Фазы реализации: память → SD card

### Фаза 1: Всё в памяти (сначала)

- **Canvas:** 368×368 нативное разрешение (PSRAM).
- **Спрайты и фоны:** Flash (PROGMEM) или PSRAM при загрузке.
- **Источник данных:** указатели на `const uint16_t*` в PROGMEM.
- **Цель:** Рабочий реворк без масштабирования, без SD.

### Фаза 2: Чтение из SD (позже)

- **Когда:** После стабилизации Фазы 1.
- **Схема:** SD → загрузка скина в PSRAM при старте/смене скина → отрисовка из PSRAM (без задержек).
- **Fallback:** Базовый скин (Golem) всегда во Flash — работает без карты.
- **Структура на SD:** `/skins/<name>/idle_*.raw`, `attack_*.raw` и т.д. (формат RGB565 raw).

### Подготовка к Фазе 2

При реализации Фазы 1 заложить абстракцию доступа к спрайтам:

```
// Вместо прямого copyProgmemToPet(idle_1) —
// функция getSpriteFrame(skinId, animType, frameIndex) → const uint16_t*
// Сначала возвращает из PROGMEM, позже — из PSRAM-буфера (загруженного с SD).
```

Так добавление SD не потребует переписывания `ui.cpp`.

## 9. Порядок работ (предлагаемый)

### Фаза 1 (в памяти)

1. **Определить концепт** — какой скин (Dragon/Robot/другой), какой стиль UI.
2. **Переход на нативное 368×368** — canvas, убрать ScalerGFX, обновить координаты.
3. **Нарисовать спрайты** — нативное разрешение (176×169), начать с Idle (4 кадра).
4. **Добавить остальные анимации** — egg, hatch, attack, dead.
5. **Подключить скин** — `petSkin` в Settings, переключение в `ui.cpp`.
6. **Обновить UI** — фон 368×368, layout, иконки.
7. **Опционально** — спрайты по стадиям (BABY/TEEN/ADULT/ELDER).

### Фаза 2 (SD card, позже)

1. Инициализация SD (SPI: CS=EXIO7, MOSI=1, MISO=3, SCK=2).
2. API загрузки скина с SD в PSRAM.
3. Переключение источника в `getSpriteFrame()`: PROGMEM vs PSRAM.
4. Сканирование `/skins/` при старте, fallback на Flash при отсутствии карты.
